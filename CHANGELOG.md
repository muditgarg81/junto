# Changelog

## 2026-06-14

- **Clear itinerary** — Added a `clearItineraryAction` server action and a trash button in the Timeline header (shown only when items exist) that wipes all itinerary items for the trip after a confirm. Vault vouchers are left intact — only the schedule is cleared.
- **Itinerary item dedup (upsert)** — Voucher/itinerary commits now route every insert through a single `upsertItineraryItem` helper keyed on `(trip_id, type, date, title)`. Re-uploading the same document or importing a full itinerary after a single voucher no longer duplicates items — a match refreshes the existing row's structured fields (`time`/`location`/`starts_at`/`ends_at`/`tz`), which also upgrades older rows created before tz support. Applied to both POST and PUT handlers; the two routes were de-duplicated into shared local `addFlightSeg`/`addStay`/`addActivity` helpers.
- **Vault detail modal reopen fix** — The `?open=<id>` deep-link effect re-ran on every `vaultItems` change, and since the vault polls `/sync` every ~3s, the booking-details modal reopened seconds after the user closed it. Now auto-opens once (ref guard) and strips the `open` param from the URL.
- **Full-itinerary PDF import** — Uploading a complete multi-day trip plan (flights + hotel + day-by-day activities) previously landed as `kind: other` with an empty form. Added an `itinerary` vault kind (CHECK constraint migrated): the OCR prompt extracts `{ tripName, flights[], stays[], activities[] }`, the voucher route normalises field-name variants and city→IATA codes (and reclassifies a rich `other`), and the commit route explodes it into one itinerary item per flight leg (tz-aware), check-in/out per stay, and one per activity. The confirmation modal shows a read-only summary with an "Import N items" button.
- **Structured flight timestamps** — Voucher flight legs now populate `starts_at`/`ends_at`/`tz` (not just legacy `date`/`time`), so the tz-aware itinerary checker can flag tight connections accurately. Added `lib/airport-tz.ts` (IATA→IANA map, India-first, plus a wall-clock→UTC-instant converter) and extended the OCR prompt to capture arrival time/date per segment.
- **Multi-segment flight vouchers** — OCR on a real round-trip ticket returned 4 legs as a nested `fields.flights[]` array, but the form/commit only modelled a single flat flight, so the confirmation form showed empty fields ("data not being pulled"). Updated the OCR prompt to formalise a `segments` array, normalised it in the voucher route (flatten first leg for the form, keep the full array), and made both the POST and PUT commit branches create one itinerary item per leg. Confirmation modal now shows a "N flight legs detected" banner.
- **Itinerary crash fix** — `lib/itinerary-checker.ts` assumed `item.date` was always a string, but the `pg` driver returns a `DATE` column as a JS `Date`, so `item.date.split()` threw `TypeError` and crashed the itinerary page the moment any item existed (surfaced after the first voucher upload created one). Added a `dateToYMD()` coercion helper routed through all four `item.date` access points (including `parseDateComponents`).
- **Voucher storage moved to Postgres** — Vercel serverless has a read-only filesystem, so the old `public/uploads` disk writes threw `EROFS` and surfaced as "OCR Parsing failed". Added a `vault_files` table (BYTEA); the voucher route now stores bytes in-DB and the signed proxy route serves them from Postgres. OCR still runs on the in-memory buffer.
- **Power/connectivity destination override** — `power` and `connectivity` intents now use a destination mentioned in the message (e.g. "adapter for Thailand") when it differs from the trip destination, instead of always using the trip destination.

- **Concierge reactive intents** — Added `connectivity`, `power`, `itinerary_check`, `trip_qa`, `concierge_other` triggers with domestic/international flag; `connectivity` and `power` are deterministic-first (zero LLM cost).
- **Concierge proactive cron** — `/api/cron/concierge` with atomic per-trip claim, 15-min interval, 429 → 30-min cooldown, `last_audit_hash` change-gate on LLM itinerary audit.
- **Security hardening** — Voucher files served via HMAC-signed 1h proxy URLs; per-partner postback secrets; LLM output sanitized (null bytes, HTML stripped, 4000-char cap); invite tokens upgraded to 256-bit with 30-day expiry; removed illegal LLM call from `/sync`.
- **Itinerary time math** — `starts_at`/`ends_at`/`tz` columns; checker rewritten with true interval-intersection overlaps, tz-aware blank-day detection, 90-min flight connection threshold.
- **Mobile architecture** — Capacitor WebView-loads-Vercel pattern confirmed; `capacitor.config.ts` consolidated with env-driven `CAPACITOR_SERVER_URL`; `android:dev` / `android:prod` scripts added.
- **Vercel cron wiring** — `vercel.json` created with `/api/cron/concierge` on `*/15 * * * *` schedule.
- **Env var docs** — `.env.local.example` updated with `FILE_SECRET`, `SESSION_SECRET`, and per-partner `PARTNER_POSTBACK_SECRET_*` entries.
- **Signed URL secret isolation** — `lib/signed-url.ts` now prefers `FILE_SECRET` over `SESSION_SECRET` so the two signing keys are independent.
